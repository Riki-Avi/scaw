Clase 4: Nube, Vulnerabilidades y Ataques

Continuamos con la Unidad 2 analizando la infraestructura en la nube, los organismos que estandarizan vulnerabilidades y cómo funcionan los ataques de denegación de servicio (DoS) y del lado del cliente.

1. Seguridad en la Nube

El debate sobre migrar infraestructura a proveedores de terceros.

  • Ventajas: Escalabilidad bajo demanda, reducción de costos en infraestructura y administración centralizada.
  • Desventajas: Dependencia del proveedor (ej. caídas masivas en AWS o Cloudflare), y problemas de soberanía de los datos (no recomendable para secretos fiscales o seguridad nacional).

2. Áreas de Seguridad (Web)

Al analizar Cliente, Red y Servidor, ¿cuál es más segura?

  • El Servidor: Es considerada el área más segura porque es la única donde tenemos control total sobre las acciones de protección (como SSH y firewalls).
  • El Cliente: Es el área menos segura; no controlamos el entorno, ni cómo el navegador manipula o altera los datos enviados (ej. Data Tampering).

3. Estandarización de Vulnerabilidades (MITRE y NIST)

Organismos internacionales clasifican y puntúan las fallas de seguridad para estandarizar las defensas.

CVE

Common Vulnerabilities and Exposures
Identificador único para vulnerabilidades en un producto específico (Ej. Angular versión 12). Permite colaborar y aplicar parches exactos.

CWE

Common Weakness Enumeration
Identifica las malas prácticas de programación que causan vulnerabilidades (Ej. Falta de validación de entradas o Cross-Site Scripting).

CVSS

Common Vulnerability Scoring System
Sistema que asigna una severidad (del 0 al 10) a cada vulnerabilidad basándose en su impacto y facilidad de explotación.

Otras herramientas clave: CPE (Enumeración de Plataformas Comunes) y NVD (Base de datos nacional de vulnerabilidades mantenida por el NIST).

4. Ataques y Prevención

Denegación de Servicio (DoS y DDoS)

El objetivo es inhabilitar un sistema saturándolo de manera que no pueda responder a los usuarios legítimos.

  • Por Volumen (Inundación): Inundar la red de paquetes masivamente usando Botnets (DDoS).
  • Por Recursos (Aplicación): Agotar la memoria o CPU de un servidor forzando respuestas complejas de la aplicación.
  • Low Rate: Utilizar una sola petición diseñada milimétricamente para explotar una vulnerabilidad y colgar el servidor.
Prevención: Las mejores prácticas modernas incluyen el uso de CDNs y WAF (Web Application Firewalls) para filtrar tráfico malicioso antes de que golpee la red privada.

Ataques del Lado del Cliente

La seguridad del navegador no debe darse por sentada.

  • Data Tampering: Modificación no autorizada de parámetros antes de enviarlos al servidor.
  • Malware y Ransomware: Programas que interceptan datos locales o cifran información extorsionando al propietario.
